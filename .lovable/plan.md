# לוח בקרה מותאם לתפקיד

לוח הבקרה יציג לכל משתמש רק את הווידג'טים הרלוונטיים לתפקידו, במקום תצוגה אחידה לכולם.

## הפריסה המוצעת לפי תפקיד

| תפקיד | KPI עליונים | ווידג'טים |
|---|---|---|
| אדמין על / מנהל מערכת | עובדים פעילים, פריטי ציוד, התראות, משימות IT | הכל: תוקפים מתקרבים (כל הדומיינים), קליטות, חופשות, התראות, עובדים בעזיבה, פעילות אחרונה |
| תפעול (operations) | עובדים פעילים, פריטי ציוד, התראות, משימות IT | תוקפים מתקרבים — כל הדומיינים, התראות, עובדים בעזיבה, קליטות, פעילות אחרונה |
| IT | פריטי ציוד, משימות IT, התראות | תוקפים מתקרבים — גישה דיגיטלית + רישיונות + ציוד בלבד, משימות IT פתוחות, קליטות |
| משפטי (legal) | ביטוחים שפגים ב-30 יום, חוזי נדל"ן | תוקפים מתקרבים — ביטוח + נדל"ן בלבד. ללא ציוד/IT/חופשות |
| משאבי אנוש (hr) | עובדים פעילים, קליטות, חופשות/מחלה היום, חוסרי החתמה היום | קליטות ועזיבות, סטטוס חופשות ומחלה, ימי הולדת, פעילות אחרונה. **ללא תוקפים מתקרבים** |
| חשבות שכר (payroll) | חוסרי החתמה החודש, בקשות תיקון נוכחות, טפסי 101 חסרים | חוסרי נוכחות, חופשות/מחלה לדיווח, סטטוס טפסי 101. **ללא תוקפים מתקרבים וללא ציוד** |
| מנהל ישיר | עובדי הצוות | חופשות/מחלה של הכפופים, חוסרי החתמה של הכפופים, ציוד בידי הצוות |
| כספים (finance) | פריטי ציוד, עלויות ליסינג/ביטוח | תוקפים מתקרבים — ביטוח + רישיונות + נדל"ן |
| עובד בלבד | — | הפניה לפורטל האישי (כמו היום) |

עיקרון: התוקפים המתקרבים מסוננים לפי דומיין (`domain`) המותר לתפקיד; אדמין/תפעול רואים הכל, משפטי רק ביטוח ונדל"ן, IT רק דיגיטלי/רישיון/ציוד, משאבי אנוש ושכר לא רואים כלל.

## מימוש טכני

1. קובץ חדש `src/lib/dashboardConfig.ts`:
   - מפה מתפקיד → קונפיגורציה: `kpis: KpiKey[]`, `widgets: WidgetKey[]`, `expiryDomains: ProtocolDomain[] | "all" | null`.
   - פונקציה `resolveDashboardConfig(roles: AppRole[])` שממזגת איחוד של כל התפקידים של המשתמש (מי שגם משאבי אנוש וגם תפעול — יראה את האיחוד), `super_admin` מקבל הכל.
2. `ExpiringAssetsCard` יקבל prop אופציונלי `domains?: ProtocolDomain[]` ויסנן את הרשימה לפיו (סינון בצד לקוח על תוצאת `useExpiringAssets`, ללא שינוי ב-RPC). כותרת הכרטיס תתאים ("ביטוחים לחידוש" כשמסונן לביטוח בלבד).
3. `src/pages/Dashboard.tsx` יעבור לרינדור מונחה קונפיגורציה: מערך ה-KPI והווידג'טים ייבנה מ-`resolveDashboardConfig`, במקום רשימה קשיחה. לוגיקת ההפניות הקיימות (עובד בלבד, dual access) נשארת.
4. ווידג'טים חדשים קלים שנשענים על נתונים קיימים:
   - `AttendanceMissingCard` (חוסרי החתמה) — מבוסס `get_attendance_gaps`.
   - `Tax101StatusCard` — מבוסס `useTax101` (רק hr/payroll/admin).
   - קיימים כבר: `OnboardingCard`, `LeaveStatusCard`, התראות, עובדים בעזיבה, פעילות אחרונה.
5. אין שינוי בהרשאות בבסיס הנתונים — זו התאמת תצוגה בלבד; ה-RLS הקיים ממשיך להגן על הנתונים.
