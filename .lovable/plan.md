# תיקון תקלת "החתמת נוכחות מרחוק"

## מה קורה היום
בפורטל העובד, לחיצה על "כניסה"/"יציאה" מנסה לכתוב ישירות לטבלת ההחתמות. כללי האבטחה של הטבלה מתירים כתיבה רק לאדמין/חשבות שכר/תפעול — לעובד רגיל יש הרשאת צפייה בלבד. לכן מתקבלת השגיאה:
`new row violates row-level security policy for table "attendance_punches"`.

הוספת החתמה שנשכחה כבר עוברת דרך פונקציית שרת מאובטחת (`add_own_punch`), אבל ההחתמה מרחוק לא.

## מה נעשה
1. פונקציית שרת חדשה להחתמה מרחוק של העובד עצמו, שמבצעת:
   - זיהוי כרטיס העובד הפעיל לפי המשתמש המחובר
   - בדיקה שהעובד מורשה החתמה מרחוק (הסימון בתיק עובד)
   - כיוון חוקי בלבד (כניסה/יציאה), חותמת זמן = עכשיו (השרת קובע, לא הדפדפן)
   - מניעת כפילות בטווח 5 דקות
   - שמירת חתימה/הערה/מיקום ב-payload, מקור `portal_remote`
2. עדכון הקוד בפורטל כך שישתמש בפונקציה החדשה במקום בכתיבה ישירה.
3. הודעות שגיאה בעברית במקום טקסט טכני באנגלית (למשל: אין הרשאה להחתמה מרחוק, כבר בוצעה החתמה).

## פרטים טכניים
- מיגרציה: `create function public.add_own_remote_punch(_direction text, _signature text, _note text, _geo jsonb)` — `security definer`, `search_path=public`, `grant execute to authenticated`.
- `src/hooks/useAttendancePunches.ts`: `useCreateRemotePunch` יקרא ל-RPC החדש.
- `src/pages/EmployeePortal.tsx`: מיפוי שגיאות לעברית בטוסט.
- ללא שינוי במדיניות ה-RLS הקיימת — הכתיבה נשארת חסומה ללקוח וכל האימות מתבצע בשרת.
